# Issue → release → evidence protocol

## First invocation
1. Read root AGENTS.md, goal.md, docs/DOCUMENTATION.md, design contracts, current master #253 and the assigned V2 issue.
2. Check latest main SHA, active PRs, unfinished runs, GitHub issue dependencies, dirty worktrees, known worker IDs and versioned personas. If the installed runtime does not expose enumeration, do not assume sessions are free.
3. Enforce one coordinator plus at most four child model sessions, only coordinator dispatches, no recursive delegation, no second forever loop and no browser swarm.
4. Verify GitHub Projects capability. Project 2 is old history; V2 Project remains unverified until a concrete URL/number is observed. Do not claim a project based on a script.

## Issue states
backlog → ready (all blockers accepted and merged) → doing → PR review → accepted → merged → deployed verified → done. Rework, blocked, deferred and superseded are explicit exceptional states. Closed issue ≠ delivered, branch CI ≠ production deployed, deployed app ≠ sponsor art acceptance.

## Developer
Take only an eligible scoped issue, lease explicit paths in a registered rw/ worktree, code the outcome and commit/push useful checkpoints; open a linked draft PR. Report reproducible tests, screenshot or motion when visual, known gaps and source head SHA. Do not directly push main, rewrite another agent's worktree or weaken old tests merely to pass.

## QA and product
Independently inspect exact immutable PR SHA. QA validates code, boundary cases, resource conservation, interaction and actual captures. Product judges strategic decisions, world-first UX and approved visual direction. Each posts role/issue/PR/SHA/verdict with exact measurements and limitations. Any new head invalidates stale verdicts.

## Release
Release engineer merges only a reviewed and accepted PR at expected head SHA; records previous main SHA rollback, merged SHA, main CI run, trusted delivery run, source_sha receipt, actual HTTPS served manifest, asset checksums and browser screenshot. Failed or missing proof => unverified, never done. Do not run repository scripts as privileged code on trusted deploy runner. Existing host adapter performs the promotion; browser verification uses one hosted Chromium instance per release.

## Visual acceptance
Reference is public/reference/approved-yard.png. Actual production app screenshot and 60s motion are evidence; numerical pixel census cannot certify style or enjoyment. Initial camera must show 3D depth, responsive road/vehicles, real freight and intentional HUD. At G1, real handset evidence and executive sponsor visual ACCEPT are separate requirements. Continue G2 only after G1 accepted.

## Quiet wait and failure
After two repeated no-progress checks checkpoint, classify blocker, and wait for an actual event. Do not fabricate activity by polling. Security concerns, unauthorized paid services, credential changes, deletion of projects or rollback need explicit approval. Preserve logs, decisions, issue comments and migrations. One short role-stamped handoff per completed assignment.
