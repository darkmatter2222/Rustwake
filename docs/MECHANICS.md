# Mechanics, currency design, and expansion contract

## Real V2 foundation
- Hidden 24x24 buildable parcel in a real rendered voxel 3D environment; road graph and 3 starter haulers.
- Starter yard includes a scrapyard extractor, depot, generator, furnace, market and crane. Physical vehicles reserve cargo at dispatch, drive to source/destination along connected road cells and deposit at the actual endpoint; no magical global output claim. Freight (#384 LOG-04) runs on four distinct ledgers — source stock, reserved load, onboard cargo, destination stock — with validated reserve→pickup→arrive transitions recorded in a persisted freight ledger; cancel, severed routes and vanished endpoints return the units to their source exactly once, reload reconciles inconsistent saves before offline catch-up, and the visible truck crates are tinted/counted from the actual onboard cargo.
- Producers and processors have localized input/output inventory; depots hold global sellable materials. Different machines have distinct build costs, recipes, power, visual state and output limits. Player chooses structure, location and roads, not a prescribed pipe chain.
- Functional current currencies: credits, scrap, ferrous, copper, aggregate, diesel, water, steel, and data. Additional registered categories: alloys, gears, circuits, relics, influence, echo shards, charters, renown. Future tiers have explicitly incomplete sources/sinks.
- Research choices and tech tiers are scaffolding; improve balance and implement actual long-tail decisions.

## Construction and site validation (#370, implemented)
- Every blueprint has an explicit cell footprint (crane is 2×3; most machines 1×1). The anchor (x,z) is the footprint's min-corner cell. R (or the Rotate footprint button) quarter-turns the placement: odd rotations swap width/depth and turn the loading bay SOUTH→EAST→NORTH→WEST. The 3D group pivot is the exact footprint center at ground level (`worldFootprint`), rotated rot×90° about Y.
- Validation is deterministic and ordered, each rejection with an exact machine code and player reason: UNKNOWN blueprint, LOCKED rank, BOUNDS outside the 24×24 land, UNSURVEYED outer ring (cells 1..22 only), PARCEL unclaimed deed, TERRAIN solid rock, SLOPE mixed heights under one footprint, COLLISION any occupied footprint cell, ROAD on a road cell, BAY blocked loading-bay approach (symmetric: you also may not pave into another machine's bay), FRONTAGE no road within 3 cells of the bay, FUNDS insufficient materials.
- Land deeds expand with real industrial rank, never a placeholder currency: tier 0 owns the north half (Cinder Yard, East Bench), tier 1 adds South Flats, tier 2 claims Far Works. Terrain is per-seed deterministic; initial road corridors and starter pads are always graded flat so every seed has legal buildable frontage.
- Hover/preview and free selection run the pure validator and NEVER deduct bank stock. A confirmed build spends the blueprint cost exactly once, ATOMICALLY (#373 BLD-04): spend, building push, stats and ledger rows commit as one transaction — an injected failure at any phase rolls the bank, buildings, stats, ledger, log, command registry and nextId back to their exact pre-command contents (capped rings restore full contents, not just lengths) and rethrows; nothing partial survives and no command outcome is recorded, so the same command id may be retried.
- `buildAt(g, type, x, z, rot, commandId)` accepts an optional command id (backward compatible — plain calls behave as before). `game.commands` is a persisted FIFO registry (last 128, sanitized on reload). A repeated id is a NO-OP that returns the ORIGINAL outcome (`duplicate: true`, same building or same rejection code/reason) with zero further spend, even at different coordinates. EVICTION BOUND (#373, disclosed): the registry keeps only the LAST 128 ids — once an id is evicted (after 128 further commands), a cross-site replay of it RE-SPENDS as a fresh command; idempotency holds only within the resident 128-id window (bounded, not a blocking defect). A duplicate plain click on an occupied cell is still COLLISION with zero spend, and a real double-click/double-tap yields exactly one building (build success auto-exits build mode). Rejection is validated against the CURRENT bank at commit time, so a preview computed against an older bank can never overspend.
- Each building records `paid` — the exact cost actually spent — and cancel/salvage refund from that provenance, durable across save/reload and ledger eviction; `paid` is validated against the blueprint on load (legacy saves fall back to the blueprint cost, never minting). Canceling an in-flight assembly (remaining > 0) refunds the full paid cost; starter buildings are protected; completed machines dismantle at floor(40%) of the paid cost plus recovered inventory. Every build/reject/cancel/salvage is recorded in the construction ledger (see engineering/ECONOMY.md). Known gap: App.jsx does not yet issue command ids, so UI taps are not idempotent end-to-end (follow-up registered in backlog/GAPS.md).
- Roads may cross a loading bay (that is frontage) but may never pave through any machine footprint cell.

## Dispatch cooldown (#558, implemented)
- A successful player `cancelFreight` arms an ABSOLUTE sim-time expiry for the cancelled source+resource PAIR in `g.dispatchCooldowns` (`{"<sourceId>:<resource>": untilElapsed}`); `deliveryCandidates` skips cooled pairs until `g.elapsed` passes the expiry. Window is `DISPATCH_COOLDOWN_SECONDS = 15` (midpoint of the issue's 10–20 s range). This makes the cancel→dismantle window winnable: on the clean base the dispatcher re-reserved the SAME pair onto the player furnace on the very next 0.5 s tick in 495/513 cancels (96.5%); with the fix, 0/32 (in-node race control, normal `createGame` + public `buildAt` furnace, no decoy seeds).
- The cooldown gates NEW reservations only. The RESERVED hard block (a live job referencing a machine rejects dismantle) and exactly-once cancellation conservation are unchanged; in-flight freight is never returned by the cooldown. Automatic returns (blockage, reload repair, fleet cap) do NOT arm it — only the deliberate player command suppresses dispatch.
- Persisted in the save. `readGame` sanitizes hostile entries (non-finite/expired/malformed drop) and CLAMPS far-future expiries to ONE window (`min(n, elapsed + 15)`), so a tampered save can never permanently lock dispatch. Expired entries are pruned each dispatch pass so the registry stays bounded by live pairs. Legacy saves without the field load clean.
- Proven by `tests/dispatchCooldown.test.mjs` (7 tests: next-tick suppression + dismantle recovery + conservation, save/reload sim-time durability, expiry boundary, per-pair granularity + RESERVED sibling hold, depot resupply variant, hostile-save sanitization/clamp, IDLE/MISSING no-op guard) and the real-UI capture `docs/evidence/558-dispatch-cooldown/` (desktop 1440x900 + phone 390x844 dpr2, PASS_NUMERIC_ONLY). The captured race variant is input-supply (depot→player furnace); the output-haul variant is proven deterministically in tests, while a real-UI OUTPUT-side capture is blocked by a SEPARATE pre-existing dispatch-starvation defect (stable building-order sort always prefers starter output candidates) tracked on #567, not fixed here.

## Desired progression
Tier 0: scrapyard, roads, trucks, active salvage and steel.
Tier 1: refined fuels, copper, foundry, player trade contracts, warehouse capacity, modular attachments.
Tier 2: circuits/gears, programmable dispatch, specialist vehicles, drones, forklifts, research branches.
Tier 3: sectors and outposts, contracts, risk and logistics network.
Tier 4: independent factory-supplied PvE defense and expeditions.
Tier 5: authoritative multiplayer realms, market escrow, asynchronous raids, co-op and protected reserves.
Tier 6: optional prestige, echo shards, land charter reset choices, faction collection, seasons and years-long progression.

For EACH currency identify earning actions, limiting constraints, sinks, inflation defenses, refund and duplicate command behavior. Never add icons for fake currencies without tracked mechanics. Long absences need deterministic jump settlement and save migration, not 12,000 recursive ticks or fabricated proofs.

## Invariants
No repeated build double charge, no cargo duplication, no resources created by a move/undo/reload loop, no illegal road through occupied building, no stuck vehicles silently losing cargo. Every hard failure offers a recoverable solution. Engines are time-independent from renderer FPS. A real-device UI pass is a separate gate.
