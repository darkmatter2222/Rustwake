# Observability, release truth and agent accountability

## Essential telemetry
- Engineering: open issues by accepted dependency, branch/PR age, current immutable heads, red tests by exact step, independently reviewed PR count, merge-to-deploy time, rollback SHA.
- Runtime: coordinator session identity and at most four child leases; task role, owned worktree, GitHub issue, actual execution start/completion, error/unknown. A queued child isn't running and CPU time isn't deliverable proof.
- Product: player construction actions, inventory movements, route completion, time-to-first-steel, production bottlenecks, research choices and recoverable errors. Distinguish synthetic fixtures from real user behavior; do not fabricate player telemetry.
- Performance: phone/desktop cold load, p95 frame, input latency, max GPU/heap and throttled scene; label actual hardware vs emulation.
- Release: package source SHA, main CI job ID, delivery job ID/status, receipt source_sha/status, served manifest/hash, browser screenshot/report, issue URL and production timestamp.

## Automated live release proof (OPS-08, #332)
The delivery workflow's `verify-live` job runs after the trusted host adapter promotes, on a GitHub-hosted runner (repository code never executes on the privileged deploy runner). `scripts/verify-live-release.mjs` fetches the public `https://home.darkmatter2222.com/rustwake/release-manifest.json`, asserts `source_sha` equals the exact promoted main commit, re-fetches the served entry JS/CSS plus `index.html` (or `--all-files` for every manifest entry), recomputes SHA-256 and byte sizes, and checks that `index.html` only references manifest-covered assets. Status contract: PASS (exit 0), FAILED (exit 1: wrong source_sha, stale/altered checksum or bytes, uncovered asset reference), UNKNOWN (exit 2: network/TLS failure, non-200, malformed manifest, invalid input SHA). FAILED/UNKNOWN fail the delivery run — never report a release verified from a red or missing proof. The receipt artifact `rustwake-live-verification-<sha>` (30-day retention) records manifest source_sha, per-file expected/served hashes, previous-main rollback target, main CI run URL and delivery run URL. Local runs honor `NODE_EXTRA_CA_CERTS` for the studio MITM proxy; Actions runners use plain HTTPS. Deterministic offline negative cases (mismatched source_sha, stale CDN JS/CSS) run in `tests/verify-live-release.test.mjs` via `npm test`. This is manifest+checksum proof only; the hosted-browser smoke below (OPS-09, #333) adds the real browser evidence.

## Automated hosted-browser smoke (OPS-09, #333)
The delivery workflow's additive `hosted-browser` job runs exactly ONE browser smoke per deployed SHA, serialized after `package`, the trusted `deploy` and `verify-live` (needs all three), on an UNPRIVILEGED `ubuntu-latest` GitHub-hosted runner — repository code never executes on the privileged deploy runner, and no browser ever runs there. The workflow-level concurrency group (`rustwake-databrick-delivery`, cancel-in-progress: false) plus the per-SHA job group `rustwake-hosted-browser-<sha>` guarantee one serialized browser instance per SHA; no local agent browser swarm substitutes for it. `scripts/capture-live.mjs <promoted-sha>` first reads the live `release-manifest.json` over HTTPS and refuses to smoke a build whose `source_sha` differs from the promoted SHA, then launches ONE headless Chromium with SEQUENTIAL fresh contexts — desktop 1440x900, then phone-sized 390x844 (emulated, no shared state) — against the live public site (`RUSTWAKE_LIVE_URL` overrides the default https://home.darkmatter2222.com/rustwake/). Per view it proves: canvas `world3d==="ready"` (stamped only after the first successful render), animation frames keep advancing, visible controls including a working Zoom in button whose canvas dataset stamp equals the synchronously applied zoom (`stampMatchesApplied`), exactly one WebGL context (instrumented, not assumed), zero pageErrors/same-origin failedRequests, no document scroll, and real screenshot artifacts. Status contract: PASS (exit 0) or FAIL (exit 1); there is no continue-on-error — a FAILED smoke fails the delivery run and leaves the release UNVERIFIED even when the deployment receipt succeeded. Screenshots + `report.json` upload as `rustwake-hosted-browser-<sha>` (30-day retention). The standing PASS_NUMERIC_ONLY local-preview caveat is retired ONLY when the release receipt cites a hosted-browser PASS at the exact deployed SHA; local `capture-v2.mjs` preview runs remain PASS_NUMERIC_ONLY by themselves. Deterministic offline tests including deliberate failure/negative cases (wrong live SHA, unreachable manifest, blank-canvas phone view, invalid URL, runner crash) run in `tests/capture-live.test.mjs` via `npm test`. Headless SwiftShader emulation still does not certify art parity, a physical handset or player enjoyment; sponsor visual G1 review of the hosted screenshots remains owed.

## Status truth
Developer DONE means code proposed; QA APPROVED means current head reviewed; MERGED means main contains implementation; DEPLOYED means trusted adapter successfully promoted; LIVE VERIFIED means public source matches SHA and controls work; G1 VISUAL ACCEPTED means executive sponsor saw working product and approved visual/world-first experience. Never collapse these into one green badge or claim done because 20 files changed.

## Incident response
Blank 3D canvas, stale asset SHA, uncontrolled scrolling, camera cursor drift, zoom controls not functioning, freight duplication, save corruption, or lost security boundary are urgent and should generate a precise issue linked to immutable source/receipt. Block release/issue closure, preserve screenshots/logs and rollback reference. Use one browser capture workflow and human/vision review, not a model-run browser fleet.

## Data privacy and retention
Collect no personal identifiers, payment credentials or chat data in game telemetry without appropriate authorization. Analytics schema/BI pipelines must document origin/consent, retention, aggregation and access. Avoid logging private tokens, raw save content, user emails or chain-of-thought. Artifacts retained per Actions policy and issue links; purge only under approved retention policy.

## Regular maintenance
Every release reconciles issue statuses, docs/backlog/GAPS.md, ADRs, screenshots and deployment proof. Coordinator summarizes factual changes and blockers at event milestones. Documentation drift is treated as a defect, not optional cleanup.
