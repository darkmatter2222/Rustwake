# World-first interaction patterns and state machine

## Purpose
Rustwake must feel like playing in a physical 3D industrial sandbox. The rendered terrain occupies the full viewport; HTML overlays explain and control the world without becoming a separate dashboard. The accepted reference is public/reference/approved-yard.png and the canonical color/typography tokens live in docs/design/PALETTE.md / tokens.json once the camera/design PR is merged.

## Global input priority
Modal confirmation > contextual inspector > active placement/road tool > camera gestures > world selection. No hidden global shortcut while typing in an input, textarea or selector. Escape closes only the topmost mode, not every layer. On desktop, left-drag on ground pans with the exact terrain coordinate retained under the cursor; right-drag or Q/E orbits, wheel zooms toward pointer, Home resets to the useful cluster. Touch: tap selects; one-finger drag pans; two-finger pinch zooms and twist rotates; pointer cancel/touch loss cannot build/spend. CAM-03 (#339): wheel, +/- buttons and pinch keep the world point under the cursor/touch centroid fixed across the **full 0.20–12 zoom range at every angle**; when that point would leave the ±90 pan envelope the **zoom clamps smoothly** (no terrain slide, no jump), while center-anchored controls always reach both limits with zero target shift. Camera change must be applied to Three camera matrix before raycast and screen-to-world picking.

## Transaction pattern
Selecting a blueprint is free. Placement preview projects the full footprint and loading bay into 3D, displays have/need and conflict reasons, keeps selection when unaffordable. Commit is an explicit distinct gesture, validates the same footprint/path/cost at time of command and spends once. Road builder selects origin → previews continuous path/blocked cells/cost → confirms exactly once; not a pipe connector or decorative line. A vehicle in transit shows source, amount, path, destination, loading state, progress and recovery if blocked. UI's visual state is a readout of simulation, not a second ledger.

## First-visit spatial guidance
The first frame must show a useful cluster with silhouettes, roads and cargo; never force a full-screen gate/lesson wall over the scene. Use one contextual hint plus optional collapsible help. Novice can find Construct, Roads, Fleet and Inspect, and produce steel without a universal Next button. Help is dismissible; preserving player intent is more important than perfect tutorial completion.

## HUD and responsive layout
Compact brand and resources at top; useful-world center clear; actionable tool dock at bottom; translucent side telemetry only where ample desktop space. Context sheet may take a bounded portion of mobile display and scroll internally; document never scrolls. At 390×844, 844×390 and wide desktop all primary functions remain reachable and at least 44 CSS px. Avoid tiny text as the sole way to understand action. 200% text may expand panels; never truncate crucial cost/recovery or place the selected building under a sheet without allowing recenter.
Contextual sheet collapse (UX-07 #365): the sheet bar is always visible while a panel is open — grip, mode title, a 44×44 toggle with aria-expanded/aria-controls pointing at the sheet body, and a 44×44 close. Toggling collapse hides the body in place (hidden attribute, panel stays mounted) without touching camera pose, selection, internal scroll or pending confirmations; focus returns to the toggle; the collapsed preference survives reload via rustwake:v2:dock-settings. Safe-area insets shift every fixed band, sheet height budgets reserve the dock/footline/rail bands, and toasts lift above an open sheet (yielding sheet height first on short/narrow viewports) so no two controls ever overlap and the world stays visible and tappable under an open panel.

## Visual state semantics
Gold/amber = constructive action/industrial work; mint = genuinely powered/connected/complete; salmon = blocked/unsafe; grey = inactive/not selected; dusty steel/earth = physical world. Always pair color with text/icon/shape. Green cannot mean a decorative animation is running when power or stock is unavailable. Decrease UI chrome emphasis rather than sacrificing world readability.

## Interaction verification
For every camera or UI change: unit test pure math, browser simulate mouse drag and wheel/zoom buttons, touch emulation with pointer cancel, and production-built desktop/phone screenshot. Assert ground point remains within **≤1 CSS pixel** under pointer after drag (exact inverse-projection conversion, see docs/design/CAMERA.md CAM-01 matrix), min/max zoom reachable without clipping or jump, game controls are visible and no document scroll. A successful React render alone is insufficient; pure-math tests alone are also insufficient — the CAM-01 regression matrix (tests/cameraMatrix.test.mjs + scripts/capture-v2.mjs desktop gesture trace) requires rendered-camera stamps and a live raycast tap cross-check at a non-default yaw quadrant, with deterministic negative controls proving the ≤1px assertion can actually fail. CAM-03 (tests/cameraZoomAnchor.test.mjs + scripts/capture-cam03.mjs desktop/phone zoom trace) additionally requires cursor/centroid anchoring across the full 0.20–12 range at all angles, smooth no-jump clamping at the envelope, dataset==applied stamps, a real two-finger pinch, and exact negative controls (zoom-only 231 px; pre-fix boundary 520.892780 px) that fail before the fix and pass after. The ±90 pan-extent clamp remains a documented limit where a **drag-pan/twist** anchor legitimately stops and must be communicated in-world; an anchored **zoom** instead clamps the zoom smoothly so its anchor never slips (CAM-03).

## Panel transitions preserve camera intent and selection (CAM-05 #341)
A panel is a readout over the world, never a camera command. Opening or closing any toolbar panel (build catalog, roads, fleet, research, market, inventory), the inspector, the UX-07 sheet collapse toggle, the freight-ledger chip, or a responsive viewport resize must keep the player's intentional pan/orbit/zoom **byte-identical** and keep the selected machine selected — even when the new panel geometry obscures it. The single decision point is the pure `transitionCamera({trigger,…})` (src/inspector.js): `panel`/`resize` return the camera by reference; `selection`/`settings` reframe only for a genuinely new, obscured selection with auto-frame enabled (UX-04); the explicit Focus button (`focus`) always reframes above the sheet; only Home/Recenter (`reset`) refits to the useful isometric home. Toolbar navigation uses `nextToolMode` (src/dock.js) and never drops selection; closing the sheet unmounts the panel but retains the selection so Inspect re-enters the same machine without re-framing. Explicit deselect stays deliberate: empty-ground tap, Escape, or dismantle — Escape clears selection without moving the camera. Resize refits nothing (`world.resize()` + retain-trigger placement).
