# Game-first interface system and responsive interaction patterns

The world is the game, not a website that happens to contain a world. Keep all major interventions contextual, visually grounded in the actual scene, and usable from one hand on a phone. The HUD should not obscure the machine or road being acted upon.

## Source components
The V2 root src/App.jsx assembles a fixed full-screen app-shell and world-container, screen-vignette, hud-top with Rustwake logo/resource rail, left-rail sector/camera controls, right-rail optional grid/fleet vitals, bottom tool-dock, panel-host for contextual sheets, center-hint, activity notices and footline. src/styles.css controls responsive positioning; src/cameraInput.js owns only world canvas gestures. Do not return to the archived V1 React HUD.

## Player interaction structure
Core tools: Inspect, Construct, Roads, Fleet, Research, Exchange; tapping resources opens inventory. Inspect entity reveals actual recipe, inventory, power and road connection, not fabricated metrics. Construct chooses blueprint and an actual ground placement; validation must explain occupied/outside/road collision/insufficient material. Roads tool chooses start/end and should show topology and cost before commit. Fleet shows real cargo reservations and vehicle state. Research consumes actual data+credits. Exchange sells actual depot inventory. Hover and keyboard focus need clear affordances.

Current foundation has build-on-tap construction with footprint rotation (R) and simplified road placement; the readable building inspector with confirmed dismantle/refund shipped via #362 (semantics below). Construction pre-commit confirmation, move/undo, bay-aware paths and perfect picking remain open issues. UI should not claim those features already work.

## Building inspector and confirmed dismantle (shipped via #362, UX-04)
The inspector is a contextual sheet in panel-host driven by a pure read model (src/inspector.js) over the authoritative simulation — it never spends, forks or fabricates economy state; every preview is unit-tested against the real transaction (tests/inspector.test.mjs). States: empty (honest guidance + construct-catalog shortcut), loading, error (missing/unknown selection) and selected. Selected shows a status chip with existing mint/amber/danger tokens (OPERATING, ASSEMBLING, STARVED, POWERLESS, NO FRONTAGE, ONLINE — no new tokens), exact status detail, power demand vs yard grid, footprint/bay facing, road-frontage reach, production recipe with level-scaled outputs, local cargo and the construction meter.

Upgrade effect: exact current-vs-next level preview (+n per output, mirroring advanceGame's n·level deposit) with an honestly disabled "Upgrade — locked" control and an aria-describedby reason — the purchase dispatch is not wired to the simulation yet (LOG track); never a fake buy.

Dismantle is two-step and confirmed. "Dismantle machine…" shows a recovery preview, then opens a role=alertdialog confirm block whose initial focus lands on "Confirm dismantling". The refund list distinguishes "40% recovery" (floor(0.4·cost) per build material, e.g. furnace 360 CR → +144 CR) from "cargo return" (100% of stored inventory); both land in the depot via removeBuilding. "Keep machine" and Escape close the confirm dialog ONLY (selection stays open) and return focus to the freshly re-mounted opener button — never the detached node. After a confirmed dismantle, focus returns to the Inspect/select tool in the dock. Confirm/Keep targets are >=44 CSS px. Gates mirror the simulation exactly: protected starter buildings (id<=6) and truck-reserved buildings show a disabled control with the exact sim reason. Canceling mid-assembly refunds the FULL blueprint cost via cancelConstruction.

Non-obscuring dock: on desktop the sheet docks on the half opposite the selected machine (auto), honoring a persisted left/right preference, and the left rail shifts beside the sheet (left-rail--beside-panel, >=771px) so controls stay reachable. On phone (<=770px) it is a bounded bottom sheet; if the machine falls under it, a focus pixel in the clear upper zone reframes the camera through pinGroundToPixel/setView/applyCamera only — #307 applyCamera/stampCamera invariants are never rewritten. A "Focus machine in clear view" fallback button appears whenever occlusion is detected. "Keep machine in view" (autoFrame) and dock side persist under rustwake:v2:ux-settings — player preference only, never economy. Escape layers topmost-first: confirm dialog, then selection/tool.

## Actionable resource strip and freight ledger (shipped via #359, UX-01)
The top strip shows the six headline resources (credits, scrap, iron, steel, fuel, data) at EVERY viewport — nothing actionable is hidden behind an overflow menu on phone. Each chip is a >=44×44 CSS px button painting the authoritative depot balance, a ⇄n badge when real truck cargo is reserved, and a text+icon flag (⚠ CRITICAL / ◔ delivery pending) derived from the same starvation precedence as the inspector. A desktop-only "N SHORT" alert summarizes critical shortages; at <=1150px the per-chip flags carry the signal so the strip never wraps into the left rail. The strip stays one row (max-width min(62vw,760px)); on phone it is a 7-column grid (6 chips + ledger opener) under the brand row.

All numbers come from a pure read model (src/resourceStrip.js) over the authoritative simulation — it never spends, forks or fabricates balances; every derivation is unit-tested against real sim transactions (tests/resourceStrip.test.mjs, 22 tests incl. #384 onboard pickup and cancelFreight returns). Semantics: depot = g.bank; machines = sum of building inventories; reserved = physical freight in transit, counted ONCE per truck — onboard v.cargo after the #384 pickup transition, else the reserved v.job amount (assignJob already take()s it from the source bag; job and cargo hold the same units, never summed together); committed = blueprint cost of buildings still assembling (already spent by buildAt, full refund on cancel — shown for context, NEVER added to the physical total); yard total = depot + machines + reserved. Capacity: the simulation exposes no storage cap even after the #384 LOG-04 freight ledgers merged (reserve/pickup/arrive/return are auditable in g.freightLedger, but no capacity ledger exists), so the ledger honestly says "No cap" and the gap is recorded in GAPS.md. Locked prestige rows (relics, influence, shards, charters, renown) render LOCKED with "later progression" copy — no fabricated earnability.

Shortage states mirror sim truth: CRITICAL iff depot + inbound job cargo cannot cover the starving machines' next-cycle need (epsilon 1e-7, same fits() rule); delivery-pending (amber) when the depot can cover it and trucks dispatch automatically; POWERLESS/NO FRONTAGE machines are never reported as starved. Shortages sort critical-first and each row opens the exact per-resource breakdown.

Tapping a chip (or the ⋯ opener) opens the Freight ledger sheet in panel-host: shortages first, then the selected resource's breakdown (depot / in machines / reserved / committed / yard total / capacity), then the full 17-material list, then the transaction ledger behind a persisted disclosure toggle (aria-expanded, last 12 real g.ledger entries, honest "No transactions recorded yet." empty state). Loading state shows a spinner card; brownout shows a grid warning instead of fake starvation. The sheet scrolls internally (bounded max-height, flex:none scroll regions) and never moves the world center on open/close/resize — #307 applyCamera/stampCamera invariants are untouched. Escape closes the sheet (UX-04 confirm-dialog layering unchanged). Disclosure preference persists under rustwake:v2:strip-settings (separate from the inspector's rustwake:v2:ux-settings; player preference only, never economy).

## Desktop layout
>=1150px full viewport with resource strip top center and compact right telemetry optional, left identity/camera controls, bottom centered dock. At 768–1150px collapse secondary metrics before shrinking text; prioritize unobstructed active factory. Mouse left ground drag pans with cursor-locked grip, right drag/Shift rotates/tilts, wheel zooms about cursor, Q/E orbit, Home reset, number shortcuts select tool, arrow keys pan, Escape dismisses.

## Phone layouts
<=770px: two-row brand/resource strip, left context camera buttons, bottom tool dock, side vitals hidden, internal-scrolling inspector capped about 46dvh. At landscape 844×390, reduce overlay vertical height and keep center/roads usable. All camera actions have visible accessible alternatives with >=44 CSS px targets. ## Fleet logistics panel (shipped via #363, UX-05)
The Fleet tool opens a contextual sheet driven by a pure read model (src/fleet.js fleetState) over the authoritative simulation — it never reserves, spends, forks or fabricates freight state. Job validity mirrors reconcileFreight exactly (phase toSource/toDest, positive finite amount, in-bounds route legs), so a job the save/reload repair would strip is never presented as live freight. One row per vehicle in simulation order shows name, a text state chip (Available for dispatch / Driving to pickup / Loading at bay / Delivering cargo / Route blocked / Load needs repair / No road frontage / No connected route — color never carries the signal alone), source→destination endpoints and resource; disabled or idle vehicles are never shown as hauling. Totals (active n/m, reserved, onboard) and the selected-truck detail (reserved load, onboard cargo, progress, ETA, bay queue) equal the sim's own job/cargo fields tick-for-tick: progress = (segment+progress)/(routeLen−1), ETA = remainingCells/speed with the moveVehicle speed formula verbatim, (v.speed||2.1)·(fleet research ? 1.18 : 1). The bay queue lists every truck serving the same bay ordered by remaining cells (AT BAY first).

Cancel freight is a real cancelFreight transaction, never a UI ledger edit: the reserved/onboard units return to the source bag exactly once and the fleet totals conserve; the simulation may legitimately re-dispatch the idle truck on the next frame, which is honest behavior, not a defect. Follow-camera ("Keep truck in view") moves the camera ONLY through public world.setView/applyCamera, preserving the #307 isometric pose (yaw 45, elevation 35.264, zoom unchanged) and pinning the truck to the clear-zone focus pixel (fleetFocusPixel) that sits above the phone sheet; world.resize() never refits. Tapping a truck in the world (truckAt within TRUCK_TAP_RADIUS_CELLS = 0.65 cells) inspects it via choose("fleet"), which clears any armed road origin — a truck tap can never mis-trigger road construction, and a ground tap outside the radius still arms a road origin normally. Escape layers topmost-first and otherwise calls choose("select"): it clears the road origin AND exits road mode (the center-hint unmounts; re-entering Roads shows TAP A START CELL).

Honest locked/unaffordable states: "Build truck" stays disabled with the exact reason — vehicle manufacturing is not wired to the simulation yet (#280), the yard dispatches its existing haulers; the road-build hint shows the real per-segment cost (3 AG + 4 CR, ROAD_SEGMENT_COST) and NO_ROUTE trucks show the stuck code with a build-roads recovery action. Empty fleet shows honest guidance, never fake rows. Settings (showIdle, followCam) persist under rustwake:v2:fleet-settings, isolated from the save and from ux-settings/strip-settings/dock-settings. Styling reuses the existing petroleum panel surfaces and --amber/--mint/--danger tokens (no new design tokens); rows are real focusable buttons with >=44px tap targets and visible focus rings.

Tests: tests/fleet.test.mjs (25 read-model tests cross-checked against real sim transactions — dispatch, pickup, cancel returns, route severance, reload reconcile) and tests/fleetWiring.test.mjs (8 wiring tests: panel rendered for mode==="fleet", follow pose preservation, truck-tap gate incl. deterministic negative, prefs persistence). ## Actionable in-world alarms and NOTICE toast gesture safety (shipped via #364, UX-06; bundled #548)
Alarms are a pure read model (src/alarms.js alarmsState) over the authoritative simulation — it never spends, forks or fabricates state; every verdict derives from the sim's own exports (powerStatus, connectedToRoad, nearestRoad, roadPath, canAfford, unlocked) and the UX-01 resourceStripState, so an alarm can never disagree with the authority or with the strip/inspector. Four classes, each with a problem AND a novice-actionable remedy: power (GRID BROWNOUT, exact demand-vs-supply MW), road (NO ROAD per completed machine without frontage, exact x,z and ROAD_REACH), starvation (mirrors the UX-01 shortage ids/severity exactly, epsilon and precedence included) and storage (BAY BACKUP when a connected machine holds >=TRUCK_LOAD=15 output units with no pickup truck assigned; disconnected bays are owned by the road alarm, never double-counted). Eight states are rendered honestly: ready, processing (turbine assembling, countdown detail), unaffordable (exact cost + Exchange alt-action), locked (producer gated behind a named tier), blocked (no source exists / no connected route), plus model-level loading (spinner chip), empty (✓ YARD NOMINAL / NO ALARMS) and error (ALARMS PAUSED, role=alert, save unreadable). Severity is NEVER colour alone: every chip carries a class icon (⌁ ⚠ ◔ ▤), the explicit word CRITICAL or WARNING, a title and full problem/remedy text; critical sorts first, then power/road/starvation/storage, deterministic for a given yard.

Problem text follows WHAT/WHERE/DO: WHAT is wrong (demand exceeds supply, no frontage, units held), WHERE it is (machine name + grid x,z, or the resource and its starving machines), and DO is the remedy sentence with real costs (costText of the actual blueprint, ROAD_SEGMENT_COST 3 AG + 4 CR per segment). The one-tap remedy routes into the SAME camera-neutral tool paths as the dock (choose/openLedger — no transitionCamera, no selection change, #307/CAM-05 invariants hold): build actions pre-select the exact blueprint (setBuildId) before opening the construct catalog, road actions open the road engineer with the bay coordinates in the notice, fleet/market/inventory open their real sheets. Unaffordable remedies add a "Sell surplus at the Exchange" alt-action instead of a dead end. The inspector shows the same alarms contextually for the selected machine (alarmsForBuilding, plus the grid alarm for powered machines) with per-alarm fix buttons. Escape layers topmost-first: an expanded alarm detail closes before the CAM-05 tool/selection Escape block (byte-identical to main), returning focus to the originating chip (rAF-observed); an sr-only role=status aria-live=polite region announces the full alarm list; reduced motion disables the detail entrance animation; every chip, toggle, collapse and remedy target is >=44 CSS px.

Geometry: desktop the rail lives in the left HUD column (max-width 272px, max-height 100dvh−490px, internal scroll) with sticky bottom remedy actions so the fix is reachable even when copy overflows. On phone (<=770px) the rail becomes a single 44px-tall TOP horizontal strip (order:-1, overflow-x:auto, touch-action:pan-x, overscroll-behavior-x:contain) — every alarm AND the warnings/collapse controls stay in the strip, nothing hidden — and the expanded detail is a position:fixed bottom sheet (left/right 8px+safe, bottom 96px+safe above the dock, max-height max(170px,min(320px,100dvh−524px−safe))) whose top sits strictly below the canvas centre (measured top 480.23 > 422, bottom 748 <= 844 at 390×844) with internal scroll and sticky 44px actions. ## Components and states
Each major panel needs: empty, available, selected, unaffordable, building, operating, starved, powerless, full storage, stuck route, saving, recovery, offline and error. Provide next available player action, not a universal next-button ladder. Colors communicate with text/icons, not color alone. Modals return focus to opener; keyboard and screen reader entity list is mandatory for final acceptance. Reduced motion must preserve information and simulation, not erase controls.

## Typography, colors and geometry
See tokens.json/PALETTE.md: condensed Barlow Condensed display, DM Sans text, petroleum-charcoal panels, warm amber action, mint valid status, salmon error, neutral grey machinery. Use 4/8/12/16/24px spacing rhythm and legible type hierarchy; avoid a crowded data dashboard. Hold a clear camera view even with a contextual panel open.
