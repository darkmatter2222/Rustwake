## Transparency — first run failed, shell fixed, nothing relaxed

The first capture run passed 68/73 and exposed a **real geometry bug**: as a
shrinkable flex item in the HUD column, the phone sheet shared the column's
shortfall with the lead and rendered **274.2px (32.5vh) / 378.4px (44.8vh)**
instead of the contractual 35/70vh. The unit tests assert the declared style
(jsdom does not layout), so only the running build caught it.

Minimal fixes (this branch, `src/ui/shell/shell.css`):
1. `.shell-sheet { flex-shrink: 0 }` — the sheet keeps its band; the lead
   already has `min-height: 0` and its own declared scroller, so it yields
   first (measured: lead 314.6px collapsed, 19.2px expanded; at 200% text the
   toolbar stays fully on-screen, 776..836 of 844).
2. With the true 70vh band there is no sky left above the painted chrome, so
   the camera zoom stack (bottom-anchored via `--shell-zoom-clear`) would sit
   off-screen (measured y=-125). It now stands down while the phone sheet is
   expanded or text-large-tall, and returns on collapse. Pinned by a CSS
   literal assertion in `tests/ui/shell-49.test.tsx`.

One harness expectation was also wrong (not a shell bug): it assumed a top
toolbar; the toolbar is the bottom bar, so the check became vertical
non-overlap (inspector bottom <= toolbar top). Thresholds were NOT relaxed;
the capture was re-run to **73/73 at the clean SHA above**.
