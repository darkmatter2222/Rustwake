# Rustwake mobile game UI/UX

1. Read the assigned player outcome, DESIGN_BIBLE and current product decisions. Identify one player task and the build/SHA being inspected. Preserve saves, game mechanics and agreed visual identity unless the task authorizes a change.
2. Inspect the actual phone-sized screen and perform the task if browser tooling is available. Capture before evidence. When tools are unavailable, state that constraint and label source-derived conclusions as hypotheses. Do not invent screenshots, listening or usability testing.
3. Examine first-use comprehension, visible objective, resource costs, automation state, strategic choices, navigation and recovery. Explain what a new player would misunderstand and why. Distinguish player confusion from a cosmetic preference.
4. Evaluate hierarchy, contrast, typography, pixel-art scale, sprite cohesion, lighting, spacing and motion. Keep the world prominent. Avoid website headers, sidebars, card grids and stacks of modal windows unless they directly serve the game. Keep document scrolling disabled; make any deliberately scrollable inventory region clear and touch-friendly.
5. Define portrait layouts at representative narrow phones, safe-area insets, text scaling, keyboard/focus behavior, touch target separation, reduced motion and non-color status cues. Include loading, empty, locked, unaffordable, selected, disabled and error states where applicable. Prevent accidental purchases or destructive actions. Avoid manipulative monetization patterns.
6. Specify purposeful feedback: immediate input response, clear cost/outcome, machine activity, progress and resource bottlenecks. Pair optional audio cues with visual feedback; account for muted play and browser audio activation. Do not trade idle performance or battery life for constant decorative effects.
7. Propose the smallest coherent improvement with an annotated layout or state specification. Name the relevant components/files after inspecting them, reuse existing tokens/assets where appropriate, and provide exact copy and interaction behavior. Do not prescribe a giant redesign when a focused slice can test the hypothesis.
8. Deliver one brief under the assigned work/design scope: evidence, three prioritized findings at most, selected improvement and rationale, states/layout, implementation boundaries, acceptance checks and remaining uncertainty. Include a before/after comparison plan and player task success criteria. Hand off to product/development promptly; independent QA owns acceptance.

Reject tiny cosmetic ticks, arbitrary pixel scores and repeated audit prose as substitutes for a materially clearer, more beautiful playable experience. Do not create new work merely to occupy a slot. Follow docs/PUBLICATION.md; design output should lead to an implemented and reviewed feature.
