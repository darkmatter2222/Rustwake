**Three defects that need another pass**

1. **A3-1's named instrument cannot certify its own criterion.** `docs/evidence/2026-11-06-art003-census-after.json → sheet.matrix` is byte-identical to `2026-11-06-art003-census-before.json` (all 15 pairs, min 11.6 in both), so the acceptance line "the after-matrix must differ from its own before-copy" is not met by the shipped artifact. It is not a copy - my `r1` run reproduces it - it is a **geometric invariant**: `SHEET()` compares absolute pixels over the *union* box, so a pixel inside exactly one box is always unequal (`"r,g,b"` vs `"bg"`) and the painted art never enters the number. Proof: `work/review/ART-003-r1/_geom.mjs` recomputes all 15 values (90.4 / 58.3 / 42.9 / 34 / 11.6 / 90.5 / 58.3 / 43.1 / 14.1 / 90.1 / 58.3 / 17.8 / 90.5 / 24.2 / 37.5) from the layout constants alone, with no pixel read at all. Fix: compare each role's own 32-unit box in **aligned local coordinates** (as the unit-resolution test already does), or use the per-cell 58x58 window - PR #26's `scripts/art003-census.mjs` already does exactly this.
2. **The A3-1 matrix covers 4 of the 8 machine blueprints.** `ids6 = [dock, sorter, furnace, wireMill, signalLab, drone]` includes the dock and the drone (neither is a machine) and omits `generic, polymerRecycler, copperSeparator, platePress, circuitAssembler`, which are precisely the bar-on-a-frame family the Issue's problem statement is about. Measuring those rows with the same `grayUnit`/`differingPct` math: generic/polymerRecycler **27.5**, generic/copperSeparator **27.5**, polymerRecycler/platePress **27.5**, generic/platePress **28.1**, copperSeparator/circuitAssembler **28.1** — i.e. the eight-machine set's true minimum is **27.5 %, under the named 32 % floor**. Visible confirmation: in `sheet-900x420.png` the five lattice glyphs differ only by which 3-unit row a bar sits on. Fix: extend the id list to all eight blueprints plus `generic` and raise the ones that fall short (a one-unit offset bar is not an identity mark; give each of the four a distinct outer element the way the mill's rings and the lab's mast already have).
3. **The `output-blocked` settle has zero visible amplitude.** Measured rust (`#c9713a`) rows for `status: "outputFull"` are identical at all six quantised frames: `326:11, 327:11` — always 11 px wide. Reason in `src/game/renderer/scene.ts`: the unconditional bar `rectOf(p.x - 9*s, p.y + 10*s, 6*s, 2*s, statusColor)` and the animated bar `rectOf(p.x - 9*s, p.y + 10*s, (pulse ? 4 : 6)*s, 2*s, same colour)` are the same rect in the same colour, so the 4-unit draw is fully covered by the 6-unit one. The unit test passes because it inspects the logged `rect` arguments, not the frame. Fix: paint that bar once with the computed width (`const barW = machine.status === "outputFull" && pulse ? 4 : 6`), or move the settle to its own row like the `powerLimited` tick (`y + 13*s`). Reproduction: `node scripts/…` → `work/review/ART-003-r1/_blocked_bar.mjs`.
