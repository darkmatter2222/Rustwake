DEF-002 · P3 · developer

favicon request answered by the SPA HTML fallback (no icon file in the release)

measured

The tab shows no icon: one console 404 (site root) plus one HTML body where an image is expected (app path).

Hypothesis and acceptance

The built index.html declares no link rel=icon, so the browser asks the site root instead of the /rustwake/ asset. Corrected measurement (OPS-009-g1): the site-root request /favicon.ico -> 404 with a 153 B text/html body, while /rustwake/favicon.ico -> 200 with 778 B text/html - that 200 is the SPA HTML fallback, not an icon, because the release directory carries no favicon.ico. So the earlier 'favicon serves 200' claim was the HTML fallback answering, and the app root route itself is the same 778 B text/html fallback.

  • a real icon file present in the release directory plus a relative link rel=icon href="./favicon.ico" yields an image/png (or image/x-icon) response for the icon request, not 778 B of text/html
  • no console 404 and no HTML-as-icon body for the icon request while /rustwake/ keeps serving the hashed entry
